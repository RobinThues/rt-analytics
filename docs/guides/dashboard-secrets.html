Dashboard secrets

How to keep the secrets of the rt-analytics dashboard in Chrome's Google Password Manager. Written for Robin, checked on 16 October 2026.

Why

The secrets live only in Vercel (production, "sensitive", so they cannot be read again) and in local files that git ignores. If a local file is lost or a Vercel variable has to be set again, you need the value from a safe place. One entry per secret in Google Password Manager is that place. The copies in the Windows Downloads folder stay where they are.

1. Turn on on-device encryption first

With on-device encryption only your devices hold the key to your saved passwords; Google cannot read them.

  1. In Chrome, open the menu at the top right (three dots) and go to Settings, then Autofill and passwords.
  2. Open Google Password Manager, then Settings.
  3. Under On-device encryption, select Set up and follow the prompts.

Or go to passwords.google.com, open Settings and select Set up under "On-Device Encryption".

It cannot be turned off again. If you lose your Google password and also lose access to every device that is signed in, you lose all saved passwords. Before you start, check that the recovery phone number and recovery email of your Google account are up to date. After a password reset, confirm the new Google password in Password Manager right away.

2. How to add one entry

  1. Open Google Password Manager: menu (three dots) > Passwords and autofill > Google Password Manager, or type chrome://password-manager/passwords in the address bar.
  2. Select Add.
  3. Fill in Site, Username (the variable name) and Password (the value), then select Save.
  4. Open the new entry, select Edit, write the note from the list below, and select Save. Notes get the same protection as passwords.

Copy values from the source with copy and paste, never by typing. Do not paste values into chats, tickets or this repository.

3. The entries

  • Session secret, production

    Site
    https://rt-analytics-dashboard.vercel.app
    Username
    BETTER_AUTH_SECRET
    Value from
    Vercel project rt-analytics-dashboard, Production. It is a sensitive variable and was generated by a script without showing it, so it cannot be read. To get a value you can store: create a new one with openssl rand -hex 32, save it here first, then replace the variable in Vercel and redeploy. Everyone has to sign in again after that.
    Note
    rt-analytics dashboard, session cookie encryption, production (Vercel, sensitive)

  • Session secret, local

    Site
    http://localhost:3000
    Username
    BETTER_AUTH_SECRET
    Value from
    apps/dashboard/.env.local
    Note
    rt-analytics dashboard, session cookie encryption, local only (not the production value)

  • Google sign-in client

    Site
    https://console.cloud.google.com
    Username
    GOOGLE_CLIENT_SECRET
    Value from
    Google shows an OAuth client secret only once, when it is created. If you did not keep it, open project robin-thues, Google Auth Platform > Clients, open the dashboard's client and add a new secret (secret rotation). Store the new value here, set it in Vercel (Production, sensitive), redeploy, then disable the old secret.
    Note
    rt-analytics dashboard, Google sign-in (OAuth web client). Client ID: put the GOOGLE_CLIENT_ID here too, it is not secret.

  • Playwright test login

    Site
    http://localhost:3300
    Username
    DASHBOARD_TEST_LOGIN_SECRET
    Value from
    apps/dashboard/.env.local (optional: a new random value works just as well)
    Note
    rt-analytics dashboard, end-to-end test login, local only, never in Vercel

4. Not secrets: no entry needed

GCP_PROJECT_ID, GCP_PROJECT_NUMBER, GCP_SERVICE_ACCOUNT_EMAIL, GCP_WORKLOAD_IDENTITY_POOL_ID, GCP_WORKLOAD_IDENTITY_POOL_PROVIDER_ID, BETTER_AUTH_URL, DASHBOARD_ALLOWED_EMAILS, the dataset names and the cache and byte cap settings. They are in Vercel and in the local helper claude-tmp-helpers/dashboard-vercel-env.sh (not in git), and vercel env pull brings them back. The dashboard itself has no service account key: it reaches BigQuery through Vercel OIDC and workload identity federation.
